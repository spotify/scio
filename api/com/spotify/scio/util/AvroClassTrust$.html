com.spotify.scio.util

AvroClassTrust

object AvroClassTrust

Avro 1.12.1+ validates every class it loads by name against ClassSecurityValidator, and 1.12.2 rejects classes outside the packages listed in org.apache.avro.SERIALIZABLE_PACKAGES, avro generated classes included. That system property is read once and can't be passed to Dataflow workers. install extends the global validator to also trust:

  • classes annotated @org.apache.avro.specific.AvroGenerated, i.e. records, enums and fixed generated by the avro compiler
  • DefaultTrustedClasses, the JDK classes avro reflect tags fields with as java-class or java-key-class, e.g. java.math.BigDecimal string fields and java.util.List arrays. Avro 1.11.4 to 1.12.0 trusted their whole packages by default, java.io and java.net included, which 1.12.1 dropped. java.io.File and java.net.URL aren't trusted by default
  • arrays of trusted classes or primitives
  • classes given to trustClasses, e.g. by ReflectRecordDatumFactory for its record class and the classes of its fields
  • classes in the packages given to trustPackages, or with the --avroTrustedPackages pipeline option, e.g. reflect records such as classes with @DefaultCoder(AvroCoder.class)

Other classes are still checked by the validator previously in place.

Avro is accessed by reflection, since scio-core doesn't depend on it, and skipped on versions without ClassSecurityValidator.
